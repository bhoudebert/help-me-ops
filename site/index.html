Oh, help me, ops.

Ask your AI assistant what went wrong in production. It searches your logs, database, metrics and health checks, follows your team's playbook, and answers with the likely cause, the evidence, and what it still doesn't know. It never changes a thing.

How it works

  1. You ask in plain words, in Claude Code, Codex or GitHub Copilot: the model is the one you already pay for.
  2. It follows your method. It settles the app and environment, takes your playbook for this kind of problem, and reads your sources, read-only.
  3. It concludes with its evidence: each line quotes its source and time, and what is unknown is said, not guessed.

Try it in two minutes

git clone https://github.com/bhoudebert/help-me-ops.git && cd help-me-ops
npm install
claude          # or open the folder in VS Code with Copilot, or add the server to Codex

The repository ships a small shop to investigate, in prod and staging, with a fault in prod only. No system of yours needed. The story and what to expect.

Want more than files? The same shop runs on a real PostgreSQL in Docker. The assistant reads the payments table and finds what no log says: three customers paid 165.20 EUR and have no order, while a SELECT-only user makes a write impossible. Five minutes, with Docker.

Then plug in your own

Your infrastructure is a folder you keep in your own repository and review like code. No AI or MCP knowledge needed: to add a database, Datadog, GitHub or your own API, you write a manifest and a plain function.

# addons/order/addon.json
{
  "apiVersion": 1,
  "settings": {
    "dbUrl": { "type": "string", "env": "ORDER_DB_URL", "secret": true }
  },
  "tools": {
    "getOrder": {
      "description": "One order: status and last change",
      "params": { "id": "string" }
    }
  }
}
# addons/order/tools.ts
import pg from "pg";

export async function getOrder({ id }, { settings }) {
  const db = new pg.Client(settings.dbUrl);
  await db.connect();
  const { rows } = await db.query(
    "SELECT * FROM orders WHERE id = $1", [id]);
  await db.end();
  return rows;  // the assistant quotes these
}
my-workspace/             # in your app's repository
  ops.config.json         # apps, environments, sources
  playbooks/              # how your team investigates
  addons/
    order/                # drop a folder in: it loads
    datadog/
    _health/              # _ turns one off

The tool is served to every client as order.getOrder, for each environment, always read-only. You never write the MCP part.

Credentials come from the environment, never from a file. A missing driver or a mistake skips that addon with a reason; the rest keeps working. Updating this project never touches your folder.

Start from a working one: npm run ops -- init addon billing --template api (or file, sql) writes both files with comments on what to change.

Or none to write: ready-made addons, such as a read-only rest for your own API, only need settings.

Built to be trusted with production

Read-only, enforced

Every tool declares it cannot change anything, and a test checks it. A fix is proposed for a person to make.

Prod is not staging

Sources belong to an environment. A question about prod is never answered from staging, and when it is unclear the assistant asks.

One toolbox, every client

One MCP server for Claude Code, Codex and Copilot, and a CLI. Same tools, same method everywhere.

Your method first

Playbooks in Markdown say how your team investigates. The assistant follows them before improvising.

No keys, no bill from us

The model is your client's, on your subscription. This project makes no model calls.

Specified and tested

Requirements per capability, tests against fixtures, decisions recorded. Nothing runs against a real system in CI.
